# V1.6.1 — Markdown Rendering

## Problem

Prior to V1.6.1, the AI backend returned Markdown-formatted responses but the WPF chat UI rendered them as plain text. Users saw raw syntax such as `##`, ` ``` `, `**bold**`, and `-` list markers literally on screen instead of styled output.

## Solution

Added professional Markdown rendering for AI (assistant) messages using the **MdXaml** library. User messages remain plain text. The backend, AI prompt, and response contract are completely unchanged.

---

## Architecture

```
AI response (Markdown string, unchanged)
        ↓
ChatMessage { Role = "assistant", Content = "..." }
        ↓
ChatMessageTemplateSelector
        ↓  (Role == "assistant")
AssistantMessageTemplate
        ↓
MdXaml.MarkdownScrollViewer  ←  Markdown="{Binding Content}"
        ↓
Rendered FlowDocument inside existing chat ScrollViewer
```

**User messages** follow the same selector but route to `UserMessageTemplate` — plain `TextBlock`, unchanged from V1.5.

## UI Design

- AI messages use `MdXaml.MarkdownScrollViewer` inside the existing grey bubble (`#EEEEEE` background)
- User messages continue to use plain `TextBlock` inside the blue bubble (`#DCEBFA`)
- `MarkdownScrollViewer` has `VerticalScrollBarVisibility="Disabled"` so the outer `ChatScrollViewer` handles all scrolling
- `HorizontalScrollBarVisibility="Auto"` allows wide code blocks to scroll horizontally
- Font: `Segoe UI 14px` — consistent with the rest of the application
- `Background="Transparent"` and `BorderThickness="0"` on the viewer so it inherits the bubble background
- The `Speaker` label ("AI") still appears above every assistant message in `DimGray`

---

## Template Selector

`ChatMessageTemplateSelector` (a `DataTemplateSelector` subclass) receives each `ChatMessage` from the `ItemsControl` and returns:

- `UserTemplate` when `Role == "user"`
- `AssistantTemplate` for all other roles (i.e. `"assistant"`)

No changes to `ChatMessage.cs` were needed — the existing `Role` property is sufficient.

---

## Security

- `MdXaml` renders to WPF `FlowDocument` — **not HTML, not a browser engine**
- No JavaScript is executed at any point
- No WebView/WebView2 component is used
- Arbitrary HTML in AI output is not executed — Markdig's HTML pass-through is not enabled by default in MdXaml
- Links open via `Process.Start` (the OS default browser), not via embedded browser
- No API key appears in any of the new files
- No audio data or screenshot data is logged

---

## Fallback Behavior

`MarkdownScrollViewer` is resilient to malformed Markdown — it will render whatever it can parse and display the remainder as plain text. The application will not crash on unusual AI output.

## Known Limitations

- Code syntax highlighting (colour tokens) is not enabled in V1.6.1. MdXaml supports it via `MdXaml.Plugins` with AvalonEdit, but the default style uses a monospace block without colourising. Syntax colouring can be added as a future enhancement.
- Very long single-line code content (e.g. a minified file) will cause horizontal scrolling within the bubble — this is intentional and preferable to truncation.
- Table rendering depends on the Markdown containing valid `|`-delimited table syntax. Malformed tables fall back to plain text.
