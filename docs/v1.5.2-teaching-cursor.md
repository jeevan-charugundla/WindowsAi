# V1.5.2 — HeyClicky-Style Visual Teacher Cursor

## Overview

Version 1.5.2 replaces the static Guide Me highlight rectangle with an animated AI teaching
cursor experience. When the user clicks "Guide Me" the assistant visually points at the
requested UI element — a transparent overlay appears, an AI cursor travels toward the target,
the target pulses, and an instruction bubble explains what to do.

**Safety constraints** — this feature NEVER:
- Moves the real Windows cursor (`Cursor.Position`, `SetCursorPos`, `mouse_event`, `SendInput`)
- Clicks the mouse automatically
- Types keyboard input automatically
- Launches or controls other applications

---

## User-Facing Flow

1. User types a question such as "Where is the Edit menu?" into the AI Companion window.
2. User clicks the **Guide Me** button.
3. The assistant captures the monitor the Companion window is on.
4. The screenshot is sent to the Groq vision model with a precision-focused prompt.
5. The model returns a normalized bounding box (`0–1000` coordinate space) for the element.
6. A transparent WPF overlay appears covering the full virtual screen.
7. An AI teaching cursor (circle + triangle pointer) starts at an offset position and smoothly
   travels toward the target over ~700 ms.
8. On arrival: a pulsing highlight ring appears around the target and the pulse ring animates.
9. An instruction bubble fades in near the target explaining what to do.
10. The overlay auto-dismisses after 8 seconds, or immediately when the user presses **Escape**
    or clicks the **✕** dismiss button.

The user's real mouse cursor is never touched.

## Coordinate System

### Normalized AI Coordinates (0–1000)

The Groq vision model returns coordinates in a **0–1000 normalized grid**:
- `(0, 0)` = top-left corner of the screenshot
- `(1000, 1000)` = bottom-right corner of the screenshot
- `x`, `y` = top-left corner of the bounding box
- `width`, `height` = size of the bounding box

Example response:
```json
{
  "instruction": "Click the Edit menu.",
  "target": { "x": 55, "y": 28, "width": 42, "height": 22 },
  "label": "Edit",
  "confidence": 0.92
}
```

### Conversion Pipeline

```
Normalized (0–1000) coords
   │
   ▼ Step 1: Scale to physical pixels on the captured monitor
   physX = monitorBounds.Left + (target.X / 1000.0) * monitorBounds.Width
   physY = monitorBounds.Top  + (target.Y / 1000.0) * monitorBounds.Height
   physW = (target.Width  / 1000.0) * monitorBounds.Width
   physH = (target.Height / 1000.0) * monitorBounds.Height
   │
   ▼ Step 2: Physical pixels → WPF overlay canvas DIPs
   scale  = GetDpiForWindow(hwnd) / 96.0   (e.g. 1.25 at 120 DPI)
   canvasX = (physX / scale) - VirtualScreenLeft
   canvasY = (physY / scale) - VirtualScreenTop
   canvasW = max(40, physW / scale)
   canvasH = max(20, physH / scale)
   │
   ▼ Overlay canvas child positions (DIPs relative to window top-left)
```

`monitorBounds` comes from `CapturedScreen.MonitorLeft` / `MonitorTop` / `Width` / `Height`,
which `ScreenCaptureService.CaptureScreenContaining(this)` populates from `Screen.FromHandle`.

## Multi-Monitor Support

- `ScreenCaptureService.CaptureScreenContaining(Window)` uses `Screen.FromHandle` to find
  which physical monitor the Companion window is displayed on and captures that monitor.
- `CapturedScreen` now carries `MonitorLeft` and `MonitorTop` (physical pixel origin of the
  monitor, which may be negative for monitors left of or above the primary monitor).
- The overlay window is positioned to cover the full virtual screen:
  ```
  Left   = SystemParameters.VirtualScreenLeft   // may be negative
  Top    = SystemParameters.VirtualScreenTop    // may be negative
  Width  = SystemParameters.VirtualScreenWidth
  Height = SystemParameters.VirtualScreenHeight
  ```
- Canvas coordinates subtract `VirtualScreenLeft`/`Top` so the canvas origin matches the
  window origin regardless of monitor arrangement.

## Click-Through (WS_EX_TRANSPARENT)

The overlay sets `WS_EX_TRANSPARENT | WS_EX_LAYERED` on its window extended style in
`OnSourceInitialized`. This tells Windows to pass all mouse input through the overlay to
whatever is beneath it, so the user can continue using their real mouse normally while the
animation plays.

```csharp
var current = GetWindowLong(hwnd, GWL_EXSTYLE);
SetWindowLong(hwnd, GWL_EXSTYLE, current | WS_EX_TRANSPARENT | WS_EX_LAYERED);
```

The Dismiss button overrides this for its own hit-testing area — since the transparent style
applies to the whole window, the dismiss button cannot be clicked. Instead, users press
**Escape** (hooked via `ComponentDispatcher.ThreadPreprocessMessage` to work without focus)
or wait for auto-dismiss.

## Animation Lifecycle

| Time (ms) | Phase | What happens |
|-----------|-------|-------------|
| 0 | Start | CursorCanvas made visible at start position (offset ~150 px left, ~80 px up from destination) |
| 0–700 | Cursor travel | `Canvas.Left` / `Canvas.Top` animated with `CubicEase EaseOut` |
| 700–900 | Arrival | `HighlightBorder` and `PulseRing` fade in (opacity 0→1 / 0→0.75) |
| 900+ | Pulse loop | `HighlightBorder` opacity pulsing (1.0↔0.55, 900 ms, forever); `PulseRing` scale pulsing (1.0↔1.4, 600 ms, `SineEase`, forever) |
| 800–1100 | Bubble | `InstructionBubble` fades in (opacity 0→1 over 300 ms, starting at T=800 ms) |
| 8000 | Auto-dismiss | `DispatcherTimer` fires → `Close()` |
| Any time | Escape / ✕ | `ComponentDispatcher` hook or button click → `Close()` |

All animations run on a single `Storyboard` with `BeginTime` offsets, so no blocking calls
or `Thread.Sleep` are used.

## Instruction Bubble Positioning

The bubble prefers to appear **above** the target:
1. If `targetTop - bubbleHeight - 12 >= edgePad` → place above.
2. Else if there is space below → place below.
3. Else → place at the nearest safe vertical position.

Horizontally the bubble is centered over the target, then clamped so it stays within the
virtual screen bounds (`edgePad = 16` px from each edge).

## Confidence Threshold

| Confidence | Behavior |
|-----------|---------|
| ≥ 0.75 | Show guidance with the AI's original instruction |
| 0.4–0.74 | Show guidance with "I'm not completely sure, but this appears to be: …" prefix |
| 0.0–0.39 | No overlay; adds chat message "I found a potential match but I'm not confident enough to highlight it." |
| `null` target | No overlay; adds chat message with the AI's explanation |

The server also enforces a minimum of 0.5 at the `/api/ai/visual-teacher` endpoint (returns
HTTP 422 for low-confidence results), so the 0.4 threshold in the client acts as a secondary
guard.

## AI Prompt

The `VISUAL_TEACHER_PROMPT` in `groqAIService.ts` instructs the model to:
- Return the **smallest** bounding box containing exactly the requested element.
- Return `null` target when the element is not visible rather than guessing.
- Not point to the AI Companion's own UI when answering "how do I…" questions.
- Output only JSON with no markdown fences or `<think>` tags.

The `parseVisualGuidance` function strips markdown fences, finds the first `{` … last `}`,
and validates all fields before accepting the response.

## Testing Guide

### Manual test — basic flow
1. Start the backend: `cd apps/backend && npm run dev`
2. Start the desktop app.
3. Type "Where is the Send button?" and click **Guide Me**.
4. Expect:
   - A transparent overlay appears over the full screen.
   - An AI cursor (blue circle + triangle) slides toward the Send button from the upper-left.
   - A pulsing blue ring and highlight border appear around the button.
   - An instruction bubble appears above (or below) the button.
   - The overlay auto-dismisses after 8 seconds.

### Manual test — not-found path
1. Type "Where is the File menu?" on a screen that has no File menu visible.
2. Expect: a chat message from the assistant explaining it couldn't find the element; no overlay.

### Manual test — multi-monitor
1. Move the AI Companion window to a secondary monitor.
2. Click **Guide Me**.
3. Expect: the captured screenshot is of the secondary monitor; the overlay and highlight appear
   on the correct monitor.

### Manual test — Escape dismiss
1. Show guidance, then press **Escape**.
2. Expect: overlay closes immediately; no crash.
