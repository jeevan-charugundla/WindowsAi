# V1.6 — Voice Input

## Overview

V1.6 adds push-to-record voice input to Windows AI Companion.  
The user clicks a microphone button, speaks, clicks again (or waits for the 30-second limit), and the transcript appears in the text input box. The user then chooses to Send, Guide Me, or edit the text before acting.

No text-to-speech, no wake word, no always-listening microphone, no autonomous actions.

---

## Architecture

```
User clicks 🎙
     ↓
MicrophoneRecorder.cs  (NAudio WaveInEvent)
  captures PCM audio → WAV bytes in memory
     ↓
User clicks 🔴 (or 30 s limit reached)
     ↓
BackendApiClient.TranscribeAudioAsync()
  multipart/form-data POST → http://localhost:3000/api/ai/transcribe
     ↓
server.ts  /api/ai/transcribe
  multer memory storage (10 MB limit)
     ↓
GroqSTTService.transcribe()
  openai.audio.transcriptions.create()  (Groq Whisper endpoint)
     ↓
{ success: true, text: "..." }
     ↓
Transcript inserted into QuestionTextBox
User presses Send or Guide Me
```

The desktop never holds or sees the Groq API key.  
The key lives exclusively in `apps/backend/.env` on the server.

## Backend Endpoint

### `POST /api/ai/transcribe`

**Content-Type:** `multipart/form-data`

| Field | Type | Required | Description |
|---|---|---|---|
| `audio` | file | Yes | Audio file (WAV, MP3, OGG, WebM, FLAC, M4A) |
| `language` | string | No | ISO 639-1 code e.g. `en`. Auto-detected if omitted. |

**Size limit:** 10 MB

**Success response:**
```json
{ "success": true, "text": "Where is the Settings button?" }
```

**Failure response:**
```json
{ "success": false, "message": "Voice transcription is currently unavailable." }
```

The endpoint never returns the API key, raw Groq errors, stack traces, or audio data in any response or log.

## Speech-to-Text Model

| Setting | Value |
|---|---|
| Provider | Groq |
| Default model | `whisper-large-v3-turbo` |
| Environment variable | `GROQ_STT_MODEL` |
| SDK | `openai` npm package (`audio.transcriptions.create`) |

To change the model, set `GROQ_STT_MODEL` in `apps/backend/.env`:
```
GROQ_STT_MODEL=whisper-large-v3-turbo
```

If the configured model is unavailable the endpoint returns HTTP 503 with a safe message — it does not crash.

## Microphone Behavior

### Recording lifecycle

```
Idle  →  [click 🎙]  →  Listening  →  [click 🔴 or 30 s]  →  Transcribing  →  Ready
```

- The microphone is opened **only** when the user clicks the mic button.
- It is closed **immediately** when the user clicks again or 30 seconds elapse.
- No background listening. No wake word. No always-on mode.

### Audio format

| Property | Value |
|---|---|
| Format | WAV (RIFF) |
| Sample rate | 16 000 Hz |
| Channels | Mono |
| Bit depth | 16-bit PCM |
| Library | NAudio 2.2.1 (`WaveInEvent`) |

### Recording limits

| Limit | Value |
|---|---|
| Maximum duration | 30 seconds (auto-stop) |
| Maximum upload size | 10 MB |

## Privacy

- Audio is captured only after explicit user action (button click).
- Audio is held in memory only — never written to disk, never logged.
- Recording stops when the user clicks again or after 30 seconds.
- Audio bytes are sent only to the configured backend transcription endpoint.
- The backend does not log audio bytes, base64 audio, or audio file paths.
- Audio is not stored permanently anywhere.
- Audio is not included in chat history.
- Temporary files: none — memory-only pipeline.

---

## Security

- `GROQ_API_KEY` is stored only in `apps/backend/.env`.
- `.env` is in `.gitignore` and is never committed.
- The API key is never sent to the desktop, never in XAML, never in C# source.
- The desktop communicates with the backend over `http://localhost:3000` only.
- Multer enforces a 10 MB file-size limit before any processing occurs.
- Audio MIME type is validated by both multer and `GroqSTTService`.
- The endpoint returns sanitised error messages — no raw exceptions.

## Error Handling

| Condition | UI message |
|---|---|
| Microphone not found | "Could not start the microphone. Please check that a microphone is connected." |
| Microphone permission denied | "Microphone access is unavailable. Check Windows microphone permissions." |
| Recording produced no audio | "I couldn't hear anything. Please try again." |
| Audio too large (>10 MB) | "The audio file is too large (maximum 10 MB)." |
| Unsupported audio format | "Unsupported audio format. Please use WAV, MP3, OGG, or WebM." |
| Backend unreachable | "Unable to connect to the AI backend for transcription." |
| Request timeout | "The transcription request timed out. Please try again." |
| Groq rate limit | "Voice transcription is temporarily rate-limited. Please try again in a moment." |
| STT model unavailable | "The speech-to-text model is unavailable. Please check GROQ_STT_MODEL in the server configuration." |
| Empty transcript | "I couldn't hear anything. Please try again." |
| Groq/backend error | "Voice transcription is currently unavailable. Please try again." |

## Voice → Chat flow

1. User clicks 🎙 — status shows **Listening...**
2. User speaks.
3. User clicks 🔴 — status shows **Transcribing...**
4. Transcript placed in text box — status shows **Ready**
5. User edits if needed.
6. User clicks **Send** → existing `/api/ai/chat` pipeline handles it.

## Voice → Guide Me flow

1. Steps 1–4 above.
2. User clicks **Guide Me** → existing `/api/ai/visual-teacher` pipeline handles it.

Voice input is a text-entry mechanism only. No separate AI pipeline.

## Known Limitations

- Microphone testing is manual; automated tests require a real audio device.
- The 30-second limit is enforced in the desktop. Very large WAV files near the limit may approach 10 MB — in practice 30 s of 16 kHz mono PCM WAV is ~1 MB.
- Language is hardcoded to `en` in V1.6. Multilingual support can be added by passing a different `language` value to `TranscribeAudioAsync`.
- Groq Whisper may occasionally hallucinate filler words on silent audio — the empty-transcript guard handles the most common case.
